# 固定九题写作与润色对照

本套件评估同一模型使用项目 skill 后的变化。它是基于公开任务类型和部分公开输入的
小型适配测试，不是 EQ-Bench 或 EditEval 的官方子榜，也不是作者身份检测。

[2026-10-16 首轮完整结果](results/2026-10-16/REPORT.md)提供逐题对照、全部三轮输出、
Astra 评分和保真争议。每题可读预览固定展示第一轮。

本次结果产生于 WordTact 更名前；冻结记录保留当时的名称、内容哈希和本地 Git 标识。
发布仓库使用独立历史，结果数据未因此重写。

## 固定范围

- 三道中文小说题：一题写作、两题修订。写作只比较裸模型与小说版；Humanizer 的
  主要用途是编辑，因此不把它的从零写作表现用于宣布胜负。
- 三道中文通用题：学术表达、面向同事的文档和跨段落一致性。
- 三道英文通用题：从 EditEval 所采用的 IteraTeR 人工标注测试集固定抽取。
- 生成模型：`gpt-6-luna`、`gpt-5.6-terra`；推理强度均为 `max`；每题每组运行三次。
- 明确指定 `service_tier=default`。保存调用参数；缺少服务端档位回执时只报告请求档位。
- 编辑题比较裸模型、对应语言的原版 Humanizer、项目 skill；还保留未经修改的原文。

每次生成使用独立临时目录和全新上下文。除指定 skill 及任务资料外，不允许读取其他
技能、记忆、评分材料或其他组输出。Codex 的公共系统与宿主指令仍然存在，因此“裸模型”
指不使用本次任务 skill 的 Codex 基线。实际工具读取另存为本地记录，不能只靠执行者自报。
各组都只使用一个生成 agent，按已选定的受派任务执行；不向用户追问，也不启动额外
编辑评阅者。Astra 仅事后评分，不反馈改稿。小说题只测相关的生成与修订能力，不代表
完整版的规划、正典维护和整套项目 CI 都经过行为测试。

## 评阅与证据

输入、评分量表及执行协议在运行前冻结并保存 SHA-256。失败首稿不覆盖，不因看到
结果而挑题、改稿或补规则。三次运行用于观察波动，不冒充更多独立题目。

Astra 使用 `max`、请求标准档，在不知道模型、方法和先前结果的情况下评阅。使用
1–7 的有锚点评分诊断自然度、声音、表达组织及信息密度；4 分表示合格常规稿，
未发现错误不自动得到最高分。
主要结果为成对胜／平／负，分别报告语言质量和综合可用性；事实与硬约束错误另列。
每对交换顺序复评；顺序不一致时，汇总按平局处理并公开分歧，不挑有利的一次。

原始候选、源文、评分、运行清单、失败情况和汇总全部可审阅。正文可以展示前后对照，
不能仅以一个均分宣传效果。自动测试只验证证据流程和结构，不验证文学质量。
逐题可读预览固定展示第一轮，不按分数挑样；结构化证据保留完整三轮。

逐题来源、固定上游版本和改编范围见 [SOURCES.md](SOURCES.md)，完整评阅标准见
[rubric.md](rubric.md)。英文三题都是学术材料；跨段落题的上下文约 2,800 个汉字，
本套题不能据此证明日常英文或整本书长度上的效果。

## 复现

运行器只用 Python 标准库，模型执行需要已登录且支持指定模型的 Codex CLI。
评测会调用模型并消耗账户额度。每次独立复跑使用一个全新的、仓库外的证据目录；
不要清空或复用其他轮次的目录。以下命令中的路径是示例，请替换为自己的绝对路径。

```sh
python3 -m unittest discover -s benchmarks/nine-case/tests
python3 benchmarks/nine-case/benchmark.py prepare --evidence /tmp/prose-bench-run
python3 benchmarks/nine-case/benchmark.py generate --evidence /tmp/prose-bench-run --workers 3 --timeout 900
python3 benchmarks/nine-case/benchmark.py judge --evidence /tmp/prose-bench-run --workers 3 --timeout 1800
python3 benchmarks/nine-case/benchmark.py export --evidence /tmp/prose-bench-run --destination /tmp/prose-bench-results
python3 benchmarks/nine-case/analyze.py /tmp/prose-bench-results
```

`prepare` 获取固定版本的 Humanizer，保留许可证，核对 SHA-256，并冻结本地两版 skill。
也可用 `--humanizer-root /absolute/path` 提供含 `zh/`、`en/` 的本地上游副本，各有
`SKILL.md` 和 `LICENSE`；同样必须匹配固定散列。
`generate` 一次创建 156 份独立任务，已有记录不会覆盖；`judge` 创建 18 次独立评阅。
评分者每次看到一题的匿名候选和指定比较对，不看到模型名、方法名或上轮评分。
固定随机种子只用于任务及展示顺序；模型使用宿主默认采样设置，没有设置模型采样种子。
复现指复现输入、条件与计算流程，不保证模型输出逐字相同。

冻结检查覆盖题目、评阅标准、提示词、调用参数与技能快照。CLI 日志、完整工具调用、
输入和首稿留在证据目录；公开结果保留可复核的文本、评分、映射和用量，去除本机路径
及会话标识。正常执行无需修改全局配置或安装全局技能。

不能只靠进程成功返回判断文本合格。字数、保护文字有可复现的机械检查；语义保持和
写作质量由独立评分诊断。出现传输故障时应保留原任务目录，在报告中另列补跑记录；
运行器不会把不完整首轮伪装成完整首轮，或静默重试后只留下更好的一稿。
