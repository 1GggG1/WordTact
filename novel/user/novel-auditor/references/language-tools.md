# Language evidence tools

These standard-library tools retrieve evidence and verify bookkeeping. The LLM
decides word sense, narrative function, voice and whether density is justified.
They do not identify an author or model from vocabulary, tokenize Chinese, or
replace semantic regression. The language rules are owned by
[`novel-expander`](../../novel-expander/references/anti-ai-patterns.md).

## Invocation and shared reading manifest

Run with Python 3.9 or newer. Resolve scripts relative to this skill, not the
project's current working directory. Always supply an explicit project root.

```sh
python3 <skill>/scripts/language_scan.py scan \
  --project-root <project> --manifest reading.json \
  --profile <project>/agent/audits/language-profile.json --output scan.json

python3 <skill>/scripts/language_scan.py recount \
  --project-root <project> --scan scan.json --classifications decisions.json \
  --profile <project>/agent/audits/language-profile.json --output recount.json

python3 <skill>/scripts/repeat_scan.py \
  --project-root <project> --manifest reading.json \
  --min-length 10 --max-results 200 --watch 某个称呼 --output repeats.json
```

Angle-bracket paths are placeholders to replace. JSON input paths are explicit;
the caller must discover the actual project profile and pass `--profile` when it
exists. With no profile, omit that argument to use the inherited generic list.
This never skips the LLM's search for new repeated expressions.

`--output` is optional; without it the tool writes JSON to stdout. Output paths
must not already exist; create the artifact parent directory first. The scripts never rewrite source prose. Choose new
artifact paths for subsequent scans rather than overwriting source or evidence.

`reading.json`:

```json
{
  "schema_version": 1,
  "units": [
    {"unit_id": "chapter-1", "path": "text/01.md", "complete_chapter": true},
    {"unit_id": "chapter-2", "path": "text/02.md", "complete_chapter": true}
  ]
}
```

Order is the intended reading order. `path` is relative to the project root;
absolute paths, traversal, escaping symlinks and duplicate resolved files are
rejected. Use UTF-8 files, one published reading unit per file. Explicitly set
`complete_chapter: false` for fragments. Empty units are rejected.

The reader-index tool may also support sliced `reading`/`canonical` mappings.
These two language tools deliberately reject that richer form. Supply published
reading files generated by the project's existing mapping/build process. Never
list both logical source files and their published copies: the tools cannot
infer that two different paths contain the same reading content.

Offsets are zero-based Unicode character offsets with exclusive ends. Source
SHA-256 covers the original UTF-8 bytes, including line endings; no newline or
Unicode normalization happens. A CRLF occupies two character positions.

## Project profile

This is the existing scan-rule profile. For a learned descriptive reference distribution, read
[`style-reference.md`](style-reference.md) and use `style_reference.py`. Keep the two artifacts
separate: reference quantiles do not rewrite thresholds or waive this scanner's review records.
Merge shared findings in the editorial report after verifying definitions, scope and count basis.

Save the project-specific profile at `agent/audits/language-profile.json`.
Example below uses a demonstration category, not a universal recommended limit:

```json
{
  "schema_version": 1,
  "profile_id": "project-language",
  "revision": 1,
  "scope": "本项目中文正文；单章与连续阅读",
  "calibration_sources": [
    {"path": "references/sample.md", "sha256": "record-the-real-hash", "scope": "同类叙述片段"}
  ],
  "categories": [
    {
      "id": "connector-bian",
      "label": "便的连接用法",
      "definition": "分开判断连接用法与方便、随便、便宜、顺便等词内成分",
      "forms": [{"kind": "literal", "value": "便"}],
      "thresholds": {
        "chapter_at_least": 2,
        "per_10000_more_than": 6,
        "paragraph_at_least": 2
      }
    },
    {
      "id": "sequence",
      "label": "先……再",
      "definition": "判断相同先后句式是否在累计使用中单调",
      "forms": [{"kind": "regex", "value": "先[^。！？\\n]{1,40}再"}],
      "thresholds": {"chapter_more_than": 3}
    }
  ]
}
```

Required profile keys are `schema_version: 1`, nonempty `profile_id`, positive
integer `revision`, nonempty string `scope`, nonempty `calibration_sources`, and
nonempty `categories`. Every category has a unique nonempty `id`, a nonempty
`definition`, and one or more literal or Python-regex forms. Zero-length matches
are rejected. Keep regexes bounded and avoid ambiguous nested repetitions.

`thresholds` may contain only:

| Key | Trigger |
|---|---|
| `chapter_at_least` | Deduplicated count ≥ integer, only for a complete chapter |
| `chapter_more_than` | Deduplicated count > integer, only for a complete chapter |
| `per_10000_more_than` | Count / supplied nonwhite characters × 10,000 > positive finite number; unit and rolling window |
| `paragraph_at_least` | Count ≥ integer within a nonblank paragraph block |

An omitted threshold does not suppress human-language review; it only disables
that numerical trigger. Generic defaults use each inherited attention term at
≥2/chapter, the contrast construction at >3/chapter, and the two-character dash
at >15/chapter. These are initial review triggers, not demonstrated universal
literary limits. The regex for contrast is only candidate retrieval.

Additional project metadata may record style, speaker, model/prompt observation
context and precise retention sources. The scanner counts the explicit manifest
without automatically filtering speakers: the LLM labels uses in context.
Record such metadata and calibration changes rather than silently changing a
threshold to clear a current failure. A changed profile invalidates the scan.

## Scan results and counting

The scan includes a canonical `profile_sha256`, source hashes, `scan_id`, raw
form matches, deduplicated `occurrences`, `statistics`, punctuation evidence and
a complete `review_template`. Scan status is always `NEEDS_VERIFICATION` because
contextual classification and aggregate review are still required.

Each occurrence records ID, category, source, character span, original text,
line number and 60-character context on each side. Within a category, connected
overlapping spans are merged and retain their matching form indices. Adjacent
matches stay separate; different categories stay separate. Consequently raw form
match counts, deduplicated occurrence counts and applicable-use counts are three
different quantities and must be labeled separately.

Statistics cover units, nonblank paragraph blocks and the current unit plus the
previous two supplied units. Empty paragraph/window rows are omitted; zero unit
totals remain explicit. Partial windows at the beginning are labeled by their
actual unit IDs. Frequency denominators include every nonwhitespace character
of that same supplied text, including punctuation. A cross-paragraph match is
attributed to its starting paragraph. Fragment frequency describes only that
fragment and never activates a complete-chapter threshold.

Keep actual counts when uses are retained for good reasons. Retention is an
editorial conclusion, not a subtraction from the frequency statistic. Compare
before/after and reference samples using the same profile hash, scope definition
and denominator; report absolute counts alongside rates. No automatic comparison
against a differently calibrated profile is provided.

## Fill the LLM review template and recount

Copy `review_template` from the scan into a new decisions file. The following
shape shows every field; copy actual IDs from that scan rather than these labels:

```json
{
  "schema_version": 1,
  "scan_id": "actual-scan-id",
  "profile_sha256": "actual-profile-hash",
  "classifications": [
    {"id": "hit-id-1", "applies": false, "reason": "属于方便这个词，不是连接用法", "action": "not_applicable"},
    {"id": "hit-id-2", "applies": true, "reason": "在人物答应之后接下一动作", "action": "retain"}
  ],
  "unit_reviews": [
    {
      "unit_id": "chapter-1",
      "density_reviewed": true,
      "punctuation_reviewed": true,
      "reason": "通读后核对全部命中与新的重复表达，并检查全文引语结构",
      "new_patterns": []
    }
  ],
  "density_reviews": [
    {"id": "density-row-id", "decision": "retain", "reason": "具体说明这些位置及累计密度为何必要", "occurrence_ids": ["hit-id-2"]}
  ],
  "punctuation_reviews": [
    {"id": "punct-issue-id", "decision": "valid_structure", "reason": "跨两段但属于同一说话人的完整引语"}
  ]
}
```

Every occurrence must have exactly one classification:

- `applies: false` requires `action: "not_applicable"` and a contextual reason.
- `applies: true` requires `action: "retain"`, `"revise"`, or `"unresolved"` and
  a contextual reason. All applicable uses remain counted, including revisions
  that have not actually been applied.
- A new observed word/phrase pattern goes into that unit's `new_patterns` list
  with expression and reason, is added to a justified project category, then is
  scanned. Nonempty `new_patterns` prevents this scan from passing.
- Every unit needs both review flags and a substantive reason. These are LLM
  assertions, not mechanical proof of text quality.

After semantic classification, every remaining triggered density row needs a
`retain` decision, a concrete aggregate reason and exactly all applicable IDs in
that row. The same use may legitimately appear in unit, paragraph and rolling
window reviews. If exclusions shrink the applicable set, update the copied
template's `occurrence_ids`. Obsolete template rows whose threshold no longer
triggers are ignored. Unknown or duplicate row IDs are rejected.

No remaining trigger can be cleared by claiming `resolved` without modifying and
rescanning the source. Missing density reasons, unresolved uses, new patterns,
unreviewed units or unresolved punctuation produce `NEEDS_VERIFICATION`.

Recount re-reads source bytes and recomputes the entire scan with the same profile
and protected spans. Changed sources, changed thresholds, missing/duplicate/
unknown classification IDs, altered reports and stale decisions are errors.
Pass the same `--profile` and `--protected` arguments used for the scan. After a
real edit or profile correction, create a new scan and classify its new template.

The recount reports original raw counts, semantic statistics, density outcomes
(`有据保留` or `未解决`) and overall frequency outcome (`达标`, `有据保留`,
`未解决`). `达标` describes the current version only; a claim of **修订后达标**
also requires the fixed original and actual difference retained by the caller.

Exit codes: successful scan/repeat retrieval `0`; recount `PASS` is `0`,
`NEEDS_VERIFICATION` is `3`; invalid/stale input or I/O errors are `2`. A recount
PASS approves only these language checks, never story facts, semantic regression,
reader continuity or final project acceptance.

## Punctuation checking and protected syntax

Use Chinese `，。；：？！、`, outer `“”`, nested `‘’`, parentheses `（）`,
title `《》` and nested title `〈〉`, dash `——` (two U+2014), ellipsis `……`
(two U+2026), and name separator `·`. The scanner reports incompatible forms;
it never converts punctuation or changes sentence boundaries.

Recognized fenced/inline code, URLs, numeric decimal/version strings, technical
identifiers such as `F/A-18`, and parseable single-line JSON are automatically
protected from punctuation diagnostics. This does not remove those characters
from frequency counts. YAML outside fences, unusual URLs, exact quotations and
other technical syntax need explicit spans; there is no blanket chapter exemption.

An optional `--protected protected.json` uses:

```json
{
  "schema_version": 1,
  "units": [
    {
      "unit_id": "chapter-1",
      "source_sha256": "actual-source-byte-hash",
      "spans": [
        {"start": 12, "end": 18, "text": "exact source substring", "reason": "具体说明原样保留的技术语法或作者要求"}
      ]
    }
  ]
}
```

Replace the illustrative offsets, text and hash with consistent real values.
The checker verifies all three. It rejects whole-unit exemptions, including a
set of spans whose union covers all nonwhitespace source characters. The LLM
must still inspect the reasons and reject unjustified broad exemptions.

Punctuation issues have IDs and a `structural_review` flag. Wrong glyphs cannot
be dismissed by writing `valid_structure`: fix the source or provide a justified
exact protected range and rescan. Apparent pairing/nesting problems and
cross-paragraph quotations require contextual judgment; only these may receive
`valid_structure` with evidence. A changed quote still requires a new scan.
Balanced counts alone never establish correct ordering or correct quotation.

## Literal repetition retrieval

`repeat_scan.py` normalizes only by retaining Unicode letters and digits; it does
not lowercase, segment, synonym-match or infer named entities. It maps every
retained character to its original offset and reports both original spans,
context, normalized text and length. Default minimum length is 10 characters.

For each repeated minimum-length seed, the first occurrence is compared with
the remaining occurrences and extended to a maximal common span. It does not
enumerate every pair. Overlapping same-unit spans are explicitly labeled.
`--max-results` bounds returned matches; `truncated: true` means retrieval is
incomplete and cannot support a claim that remaining repetition is absent.
Repeated `--watch` options separately retrieve all literal occurrences of the
given expressions with exact source positions.

The LLM decides whether the repetition repeats a completed narrative function,
helps an arriving reader, creates a payoff, changes a listener's response or is
necessary naming. Literal retrieval is not a substitute for the required
5–10-chapter continuous reading or reader-index context.
