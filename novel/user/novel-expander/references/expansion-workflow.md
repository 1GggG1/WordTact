# 长篇扩写工作流

处理多章节扩写任务时读取本文件。

---

## 从大纲到章节的拆分策略

### 第一步：识别大纲颗粒度

用户的大纲通常是以下几种：

**极粗大纲**（一句话概括几万字的内容）
> "主角重生回十年前，利用前世记忆一路发展势力"

这种需要先帮用户拆成中等颗粒度，再逐章扩写。

**中等大纲**（每个情节节点有几句话描述）
> "主角到了新城市。先去找商人甲买材料。途中遇到一个被人追赶的少年，救了他。这个少年后来成为主角的重要盟友。"

这种可以直接按节点拆章。

**细粒度大纲**（接近分章大纲）
> 第一章：主角进城，描写城市的繁华。去商铺，和商人甲讨价还价。
> 第二章：回去的路上看到有人打架……

这种直接扩写。

### 第二步：拆章原则

每章应该有一个可辨识的核心变化：它可以来自冲突、发现、决定、关系移动或有代价的拒绝，
不要求每章都制造激烈对抗。

拆章的时候问自己：
- 这章的"钩子"是什么？（让读者想看下一章的理由）
- 这章结束时，局势和章首比有什么变化？
- 本章是否提供计划中的体验、理解、关系或行动价值？主线删后仍能跑通，不足以判定本章应删除。

字数分配不需要均匀。重要的转折章可以长一些，过渡章可以短。

### 第三步：确认再写

拆完章后，把章节大纲给用户确认。格式如下：

```
第X章（暂定名）
核心事件：一句话
预估字数：XXXX字
```

尚未确定的新拆章方案先确认；已有明确大纲或连续写作授权时，按授权范围直接推进。

## 多章节的连贯性管理

### 文风与措辞的基准

按[文风与措辞一致性](../../novel-auditor/references/style-consistency.md)固定本次作者约定和认可样稿版本，
逐章携带适用的短摘要，不把最近接受稿自动升级为新基准。叙述、对白、报告及不同人物场景
分别判断；情节推动的紧张、放松或关系变化可以改变表达。作者主动调整时记录生效范围，
不把新要求无条件追溯到旧章。跨章复核沿用文末的连续阅读范围，不新增全书重扫流程。

### 角色状态追踪

扩写多章时，维护一个内部的角色状态表：

- 角色当前的身体状态（有没有受伤、消耗了多少等）
- 角色当前的情绪状态
- 角色知道了什么、不知道什么
- 角色手上有什么道具/资源

每章写完后检查：角色状态的变化是否反映在了文本中？

### 伏笔和回收

大纲中出现的"后来会重要的元素"，在首次出现时要自然地提一下，但不能太刻意。

埋伏笔的技巧：
- 让它作为场景的背景元素出现，不要单独给它一段描写
- 通过角色的不经意一瞥或一句话带过
- 和当前场景的其他细节混在一起，不要让它显得特别

### 信息流控制

整个故事的信息投放应该有节奏。画一条时间线：

```
章1：建立主角的日常 → 暗示异常
章2：异常出现 → 主角初步应对
章3：揭示部分真相 → 带出更大疑问
……
```

关键原则：
- 每章都应改变读者或人物所处的局面；新信息只是变化的一种
- 连续铺垫要检查是否形成新的理解、期待或体验，不强制每章制造决定或转折
- 重大信息的揭示要有"值得等"的感觉——之前要有足够的铺垫让读者好奇

## 单章扩写的内部结构

一章可以参考以下节奏形状，但百分比只用于发现失衡，不是模板：

**开场**（全章5-10%）
- 延续上一章的情绪，或者制造和上一章的反差
- 快速建立本章的场景和状态

**发展**（全章40-50%）
- 推进核心事件
- 穿插角色互动和世界观细节
- 制造小的张力起伏

**高潮/转折**（全章20-30%）
- 本章最重要的那个时刻
- 节奏应该明显变化（通常变快）

**收尾**（全章10-15%）
- 处理高潮的余波
- 设置下一章的引子
- 不要拖，干脆利落

不是每章都要有激烈的高潮。日常章的关键变化可以是一次没被接住的请求、一个决定、
一项关系微移或一段有张力的对话；如果别的形状更适合，不要为了比例补段落。

### 场景、简述与省略

- 不可逆决定、关键发现、拒绝、策略变化和关系移动进入前景场景。
- 惯例、重复劳动、旅行过程、次要交流和已建立模式用简述压缩。
- 只连接两个清楚状态且没有新功能的过程直接省略。
- 简述中若出现真正改变行动方向的一刻，在该处重新进入场景。

篇幅追随叙事重要性，不追随钟表时长。不要把每个大纲节点平均扩成同样长度。

## 写作顺序

多章扩写时，按以下顺序操作：

1. 拆章 + 确认
2. 逐章扩写（不要跳着写）
3. 按约定交付单位反馈；已有连续写作授权时，完成规定检查后继续
4. 如果用户对某章不满意，先修改再继续

为什么不跳着写：因为前一章的细节会影响后一章。角色在第二章受了伤，第三章就不能写得跟没事人一样。线性扩写能避免这类矛盾。

## 长篇中的节奏编排

连续多章的节奏不能一直在同一个水平。参考以下模式：

**基本波形**：
```
紧张 → 更紧张 → 爆发 → 舒缓 → 日常 → 铺垫 → 紧张 → ……
```

阶段性高点的间隔由类型承诺、当前弧线和读者预期决定。固定章数只能作为密度警报：若长时间
没有不可逆变化，检查是否空转；若每章都在爆发，检查是否缺少后果和消化。

舒缓章不是水字数。它的作用是：
- 让角色消化刚才发生的事
- 展示冲突带来的后果和变化
- 为下一个紧张阶段做铺垫
- 给读者喘口气

## 和用户的协作方式

扩写长篇时，每次输出一章（或用户指定的单位）。每章输出后：

1. 到约定交付点呈报；已有连续写作授权时不中途重复请求确认
2. 如果用户说"继续"——写下一章
3. 如果用户说"这里改一下"——修改后再继续
4. 如果用户调整了大纲——更新后续章节规划
5. 如果用户说"这个角色的语气不对"——记住并在后续调整

不要一次性输出超过一章的内容，除非用户明确要求。

## 读者接续、词频与接受状态

按 sibling ci 的 project-context.md 读取适用作者约定、读者条件与已披露信息。每章写前
查询目标之前的读者索引，写后分别检查词频、语义与统一标点。只提交接受稿的索引。
三章滚动计数不替代连续阅读：默认最近十个发布章，初次建档、每新增五个接受章、旧章
实质修改时通读；不足十章读全部，不足五章注明限制。已明确授权连续写作时按授权范围
推进，不重复询问同一许可。新发现的创作方向分歧单独处理。
